## 選這個方向的理由

- 可展示的既有成果是兩台 B210 在法拉第籠內的 LTE OTA 連線、雙路徑探測工具、2026-11-12 的量測與
  互動網頁。這個方向直接建立在這些成果上。
- 2026-11-12 的量測留下一個缺口：有線路徑每次都較快，也沒有注入劣化，所以複製傳送的好處沒有被證明，
  每項也只跑一次。
- 6G／LEO 的 Neuro-Symbolic RRM 目前只有架構與虛擬碼；本方案把其中「AI 提議、規則否決、確定性退路」
  的分工第一次做成可執行的程式。
- 5G NR／Open5GS 尚未安裝或驗證，量子相關構想在 Repo 中沒有任何材料，這次都不列入主線。

## 要解決的問題

兩條路徑都不完美、而且會隨時間變化時，固定策略都不好：只走一條會在它變差時掉封包，
全部複製又多用一倍頻寬。

作法是讓控制器對每個封包決定「走 A、走 B、或兩路都送」，目標是在期限內送達的比例最高、
多送的副本最少。

| 元件 | 內容 |
| --- | --- |
| 路徑 A | LTE OTA（B210、法拉第籠內） |
| 路徑 B | 有線，加上隨時間變化的類 LEO 特性。應用層模擬，不是衛星鏈路 |
| 控制器 | 情境式多臂吃角子老虎（LinUCB），輸入為兩條路徑最近的 RTT、逾期比例、多久沒有回音 |
| 規則層 | 策略只提議；被提議的路徑連續失敗，或另一條路徑太久沒有回音時，改為兩路都送 |
| 對照組 | 只走 A、只走 B、固定 2:3 分流、全部複製、門檻規則 |

### 2026-11-14 至 2026-11-18

2. 第 1～2 天：離線環境、對照策略、LinUCB 與規則層；報告骨架。

退路：若第 3 天 OTA 無法 Attach，報告只呈現離線結果，並照實標示路徑 A 是模型、線上實驗尚在進行。

### 2026-11-19 至 2026-12-03

- 加強模型：預測下一次中斷，並與 LinUCB 比較。
- 分段調低 OTA 增益，取得真實的無線劣化。
- 現場展示：即時頁面顯示決策，並準備離線重播。
- A0 海報、7 分鐘講稿與排練。
- 平行支線，不阻擋主線：Open5GS＋UERANSIM 的虛擬 5G SA；有餘力再以 Open5GS EPC 取代 srsEPC。
  一律在容器或 VM 中進行，不覆蓋現有 srsEPC。

## 報告骨架

1. 動機：有期限的應用在單一路徑上不可靠，全部複製又浪費。
2. 背景：雙路徑分流與複製、地面與衛星的多重連線。
3. 測試平台：兩台 B210 的 LTE OTA 與 2026-11-12 的量測。
4. 方法：類 LEO 鏈路模型、控制器、規則層。
5. 實驗設計與對照組。
6. 結果。
7. 限制、未來延伸與決賽前時程。

## 不可宣稱的事項

- 這是應用層的分流與複製，不是 PDCP 層，不宣稱符合 3GPP URLLC 或 NTN。
- 路徑 B 的類 LEO 特性是模擬；每張圖都要標示哪條路徑是量測、哪條是模擬或模型。
- 無線端是 LTE，不寫成 5G。Open5GS 支線即使完成，也只能稱為虛擬 5G 核網。
- 單次結果只能寫成單次結果；沒有 OTA 上的策略比較之前，不寫「在實測平台上驗證」。
- 目前的離線結果中，LinUCB 沒有勝過門檻規則。報告需照實呈現，不挑選有利的參數。

## 執行邊界

- 每次啟動 Runtime 或 RF 都需要當次的 Owner 授權，只在關好的法拉第籠內進行。
- 不修改 `/etc/srsran/` 與現有 Lab 設定；劣化一律在應用層注入，不以 `tc` 改變主機網路設定。
- 有實質量測時補 Task Evidence Record；不寫入 Secret、Ki、OPC 或 subscriber data。
